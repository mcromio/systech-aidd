# Быстрый старт: Шаблоны дорожной карты

> **Для AI-агентов:** Как планировать и выполнять спринты по методологии итеративной разработки

---

## 🎯 Что это

Набор шаблонов для организации работы AI-агентов по спринтам и итерациям:

- **Roadmap** - стратегический план (ЧТО делаем)
- **Tasklist** - тактический план (КАК делаем по шагам)
- **Итерации** - маленькие задачи (1-3 дня каждая)

---

```
docs/
├── roadmap.md                    # Главный роадмап проекта
├── tasklists/                    # Детальные планы спринтов
│   ├── tasklist-s0.md           # Пример: MVP

    ├── README.md                # Навигационный центр ← НАЧНИ ЗДЕСЬ
    ├── GETTING_STARTED_RU.md    # Этот файл

```

## 🚀 С чего начать

### 1. Открой README.md

**Файл:** `docs/roadmap_templates/README.md`

Это **навигационный центр** со всей информацией:
- Описание всех документов
- Быстрая навигация по темам
- Сравнительная таблица
- FAQ

### 2. Изучи примеры

**Реальные примеры из проекта:**

```bash
# Посмотри как устроен roadmap
docs/roadmap.md

# Посмотри пример основного тасклиста
docs/tasklists/tasklist-s0.md

# Посмотри пример технического долга
docs/tasklists/tasklist-techdebt-s0.md
```

### 3. Используй для новых задач

**Когда создаёшь новый спринт:**

1. Открой `docs/roadmap.md`
2. Добавь новую строку в таблицу спринтов:

```markdown
| **S{N}** | {Название} | 💡 Идея | {Цель одним предложением} |
• {Работа 1}<br>• {Работа 2}<br>• {Работа 3} | TBD |
```

3. Создай файл `docs/tasklists/tasklist-s{N}.md`
4. Разбей работы на итерации (1-3 дня каждая)

## 📊 Три уровня планирования

```
┌─────────────────────────────────────────┐
│   ROADMAP (roadmap.md)                  │
│   Уровень: ЧТО делаем                   │
│   Детализация: Высокая                  │
│   Пример: "Реализовать аутентификацию"  │
└─────────────┬───────────────────────────┘
              ↓
┌─────────────┴───────────────────────────┐
│   TASKLIST (tasklist-sN.md)             │
│   Уровень: КАК делаем (итерации)        │
│   Детализация: Средняя                  │
│   Пример: "Создать модель User"         │
└─────────────┬───────────────────────────┘
              ↓
┌─────────────┴───────────────────────────┐
│   TASKS (чек-листы в итерациях)         │
│   Уровень: ШАГИ (конкретные действия)   │
│   Детализация: Низкая                   │
│   Пример: "Создать файл models/user.py" │
└─────────────────────────────────────────┘
```

## 🔄 Жизненный цикл спринта

```
1. 💡 Идея
   ↓ (добавить в roadmap.md)

2. 📋 Запланирован
   ↓ (создать tasklist-sN.md)

3. 🔄 В работе
   ↓ (выполнять итерации: 🔲→🔄→✅)

4. ✅ Завершен
   ↓ (собрать метрики, обновить roadmap)

5. 📊 Ретроспектива
   (проанализировать результаты)
```

## ✅ Чек-лист выполнения итерации

### Начало
- [ ] Обновить статус: 🔲 → 🔄 IN PROGRESS
- [ ] Прочитать цель итерации
- [ ] Изучить список задач

### Во время работы
- [ ] Писать код с type hints и docstrings (русские)
- [ ] Писать тесты параллельно с кодом
- [ ] Запускать `make format`, `make lint`, `make test`

### Завершение
- [ ] Проверить критерий готовности (bash-команды)
- [ ] Проверить 11 пунктов Definition of Done:
  1. ✅ Код написан
  2. ✅ Type hints везде
  3. ✅ Docstrings на русском
  4. ✅ Logging (не print)
  5. ✅ DRY - нет дублирования
  6. ✅ Методы < 40 строк
  7. ✅ Тесты написаны
  8. ✅ `make test` проходит
  9. ✅ `make lint` проходит
  10. ✅ Критерий готовности выполнен
  11. ✅ Ручное тестирование (где нужно)
- [ ] Обновить статус: 🔄 → ✅ DONE + дата

## 📖 Примеры из README.md

### Правильное описание в roadmap

✅ **Хорошо (высокий уровень):**
```markdown
"Реализовать персистентное хранилище для сохранения истории между перезапусками"

Состав работ:
• Выбор и настройка СУБД
• Проектирование схемы данных
• Реализация слоя доступа к данным
• Рефакторинг приложения для использования БД
```

❌ **Плохо (слишком детально):**
```markdown
"Добавить PostgreSQL"

Состав работ:
• Создать файл docker-compose.yml с Postgres
• Установить библиотеку psycopg2
• Написать класс DatabaseConnection с методом connect()
```

### Правильное описание итерации

✅ **Хорошо:**
```markdown
## Iteration 1: Модели данных для пользователей

**Цель:** Создать Pydantic и SQLAlchemy модели для пользователей
**Тест:** Миграция создает таблицу users с правильными полями

### Задачи
- [ ] Создать Pydantic модель User
- [ ] Создать SQLAlchemy модель UserDB
- [ ] Создать миграцию Alembic
- [ ] Написать тесты
- [ ] Применить миграцию

### Критерий готовности
```bash
make migrate
psql -d mydb -c "\d users"
# Output: Table "users" with all fields
```
```

❌ **Плохо:**
```markdown
## Iteration 1: Сделать всю систему пользователей

**Цель:** Реализовать пользователей
**Тест:** Работает

### Задачи
- [ ] Сделать модели
- [ ] Тесты
```

## 🎓 Частые вопросы

**Q: С какого файла начать?**
A: Открой `docs/roadmap_templates/README.md` - там вся навигация.

**Q: Как создать новый спринт?**
A:
1. Добавь строку в `docs/roadmap.md` (статус 💡 Идея)
2. Создай `docs/tasklists/tasklist-sN.md` с итерациями
3. Обнови статус спринта: 💡 → 📋 Запланирован

**Q: Сколько итераций в спринте?**
A: Обычно 3-10 итераций. Если больше 10 → разбей на 2 спринта.

**Q: Сколько длится итерация?**
A: 1-3 дня. Если больше → разбей на меньшие итерации.

**Q: Что делать если нашёл проблему в завершенной итерации?**
A: Не меняй завершенную итерацию (✅). Создай новую TechDebt итерацию.
