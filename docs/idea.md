# Концепция LLM-ассистента в виде Telegram-бота

## Описание проекта

LLM-ассистент представляет собой **полноценный ИИ-продукт** в виде специализированного бота для мессенджера Telegram с **четко определенной ролью**. Бот использует возможности больших языковых моделей (LLM) для выполнения своей конкретной функции, определенной системным промптом.

## Основная цель

Создание интеллектуального Telegram-бота с **конкретной ролью [role]**, способного профессионально выполнять свою функцию через взаимодействие с пользователями. Роль и поведение бота полностью определяются системным промптом, который хранится в файле и может быть настроен под конкретную задачу.

## Ключевые возможности

### 1. Диалоговый интерфейс
- Ведение контекстного диалога с пользователями
- Сохранение истории переписки в рамках сессии
- Поддержка естественного языка

### 2. Специализированная роль
- **Системный промпт хранится в файле** и определяет роль и поведение бота
- Каждый бот имеет **конкретную роль [role]** для выполнения четко обозначенной функции
- Команда `/role` для отображения текущей роли бота
- Возможность настройки стиля общения под конкретную задачу
- Гибкая конфигурация параметров модели

### 3. Интеграция с Telegram
- Использование Telegram Bot API
- Обработка текстовых сообщений
- Поддержка команд бота

## Концепция роли [role]

Ключевое отличие от базового ассистента — **бот является полноценным ИИ-продуктом** с четко определенной ролью.

### Характеристики роли

**Роль определяет**:
- **Специализацию**: что именно умеет делать бот
- **Стиль общения**: как бот взаимодействует с пользователем
- **Границы компетенции**: что входит и не входит в его функции
- **Формат ответов**: структура и подача информации

### Реализация роли

1. **Системный промпт в файле**:
   - Хранится в `prompts/<role_name>.txt`
   - Содержит детальное описание роли, задач, стиля
   - Легко редактируется без изменения кода
   - Версионируется вместе с проектом

2. **Команда `/role`**:
   - Выводит краткое описание роли бота
   - Помогает пользователю понять возможности
   - Устанавливает правильные ожидания

3. **Специализация вместо универсальности**:
   - Бот отлично выполняет **одну** конкретную функцию
   - Отклоняет запросы вне своей компетенции
   - Профессиональный уровень в своей области

### Преимущества подхода

✅ **Четкость**: пользователь понимает, для чего бот
✅ **Качество**: глубокая специализация = лучшие ответы
✅ **Масштабируемость**: легко создать множество специализированных ботов
✅ **Простота настройки**: изменение роли = редактирование файла промпта
✅ **Продуктовость**: каждая роль = отдельный ИИ-продукт

## Технические компоненты

### Основные модули
1. **Telegram Bot Handler** - обработка входящих сообщений от пользователей
2. **LLM Integration** - интеграция с языковой моделью
3. **Context Management** - управление контекстом диалога
4. **Configuration Module** - управление настройками и конфигурацией
5. **Role Management** - управление ролью бота, загрузка системного промпта из файла

### Стек технологий (предполагаемый)
- Python 3.10+
- python-telegram-bot / aiogram (для работы с Telegram API)
- OpenAI API / Anthropic Claude / другие LLM провайдеры
- Redis / SQLite (для хранения контекста и сессий)

## Архитектура

```
User → Telegram → Bot Handler → Context Manager → LLM API → Response
                      ↓              ↓                ↑           ↓
                Configuration    Session DB    Role/Prompt   Processing
                                                   ↑
                                              System Prompt
                                                 (file)
```

## Функциональные требования

1. **Базовые команды**:
   - `/start` - начало работы с ботом
   - `/help` - справка по использованию
   - `/role` - отображение текущей роли бота
   - `/reset` - сброс контекста диалога

2. **Обработка сообщений**:
   - Прием текстовых сообщений от пользователя
   - Формирование контекста с учетом истории
   - Загрузка системного промпта с ролью из файла
   - Отправка запроса к LLM с системным промптом и ролью
   - Возврат ответа пользователю в соответствии с ролью

3. **Управление контекстом**:
   - Сохранение истории диалога
   - Ограничение размера контекста (token limit)
   - Очистка старых сессий

## Нефункциональные требования

1. **Производительность**: Время ответа не более 5-10 секунд
2. **Надежность**: Обработка ошибок и исключений
3. **Масштабируемость**: Поддержка множественных пользователей
4. **Безопасность**: Защита API ключей и пользовательских данных

## Примеры использования

## Риски и ограничения

1. **Стоимость**: Запросы к LLM API могут быть затратными
2. **Rate Limits**: Ограничения на количество запросов
3. **Токен лимиты**: Ограничения на размер контекста
4. **Качество ответов**: Зависит от качества промпта и модели
