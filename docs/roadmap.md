## 📝 Пояснения

### Структура тасклистов

Каждый спринт может содержать несколько тасклистов в зависимости от типа работ:
- `tasklist-<код спринта>.md` - основной тасклист спринта
- `tasklist-<тип работ>-<код спринта>.md` - специализированные тасклисты

**Пример для S0:**
- `tasklist-s0.md` - основная разработка MVP (итерации 1-9)
- `tasklist-techdebt-s0.md` - технический долг и улучшения качества

### Принципы планирования

1. **Итеративность** - каждый спринт разбит на небольшие итерации (1-2 дня)
2. **Тестируемость** - каждая итерация имеет четкий критерий готовности и тесты
3. **Инкрементальность** - каждый спринт добавляет ценность к продукту
4. **Качество** - соблюдение стандартов кода на всех этапах

### Workflow спринта

```
📋 Планирование → 🔄 Разработка → ✅ Тестирование → 📦 Релиз → 📊 Ретроспектива
```

Каждый спринт проходит через:
1. **Планирование** - детализация задач в тасклист
2. **Разработка** - реализация по итерациям
3. **Тестирование** - юнит-тесты, интеграционные тесты, ручное тестирование
4. **Релиз** - обновление CHANGELOG, коммит, тег версии
5. **Ретроспектива** - анализ результатов, обновление roadmap
