# Development Workflow

> Правила выполнения работ по тасклистам спринтов (например, [tasklist-s0.md](tasklists/tasklist-s0.md))
> Для code assistant'а, разрабатывающего бота по [vision.md](vision.md)

---

## 🎯 Основной принцип

**Согласуй → Реализуй → Подтверди → Коммит**

Работа ведется **строго итерациями** по тасклистам текущего спринта (см. [roadmap.md](roadmap.md)).

---

## 📋 Процесс выполнения итерации

### 1️⃣ Начало итерации

**Действия:**
- Прочитать описание текущей итерации из тасклиста текущего спринта
- Изучить список задач
- Понять критерий готовности

**Обновить тасклист:**
```markdown
| **Iter N** | Описание | 🔄 IN PROGRESS | 🔲 | - |
```

---

### 2️⃣ Согласование решения

**Перед написанием кода показать пользователю:**

#### Предлагаемое решение
```markdown
## Iteration N: Название

### Подход к реализации

1. **Файл: src/module_name.py**
   - Класс ClassName с методами: method1, method2
   - Зависимости: Config, OtherClass

2. **Файл: tests/test_module_name.py**
   - Тесты: test_method1, test_method2
   - Моки: MockedAPI

### Структура класса

\`\`\`python
class ClassName:
    """Docstring на русском."""

    def __init__(self, config: Config):
        """Инициализация."""
        self.config = config

    async def method1(self, arg: str) -> bool:
        """Описание метода."""
        # Логика
        pass
\`\`\`

### Ключевые моменты

- Type hints везде
- Pydantic для моделей данных
- Логирование важных событий
- Try/except для внешних вызовов
```

**Спросить:** "Согласовать этот подход?"

**Ждать подтверждения от пользователя.**

---

### 3️⃣ Реализация

**После согласования:**

1. **Создать/обновить файлы** согласно плану
2. **Следовать [conventions.md](conventions.md)**:
   - Type hints везде
   - Docstrings на русском
   - Логирование
   - Pydantic модели
   - Обработка ошибок

3. **Отметить выполненные подзадачи** в тасклисте текущего спринта:
```markdown
- [x] Реализовать src/module_name.py
- [x] Написать tests/test_module_name.py
```

---

### 4️⃣ Проверка

**Запустить проверки:**

```bash
# Синхронизация зависимостей (если обновлялся pyproject.toml)
uv sync

# Форматирование
make format

# Линтер
make lint

# Тесты
make test
```

**Если критерий готовности требует ручного запуска:**
```bash
make run
# Протестировать функционал вручную
```

**Сообщить результаты пользователю.**

---

### 5️⃣ Подтверждение

**Показать пользователю:**
- ✅ Список выполненных задач
- ✅ Результаты тестов (coverage)
- ✅ Результаты lint
- ✅ Проверка критерия готовности

**Спросить:** "Итерация N завершена. Подтверждаете?"

**Ждать подтверждения от пользователя.**

---

### 6️⃣ Обновление прогресса

**После подтверждения обновить тасклист:**

```markdown
| **Iter N** | Описание | ✅ DONE | ✅ | 2025-10-XX |
```

**Отметить все задачи итерации:**
```markdown
- [x] Все подзадачи отмечены
```

---

### 7️⃣ Коммит

**Создать коммит:**

```bash
git add .
git commit -m "feat: Iteration N - Краткое описание

- Реализован ModuleName
- Добавлены тесты
- Coverage: XX%

Closes #N"
```

**Формат commit message:**
- `feat:` - новый функционал
- `fix:` - исправление бага
- `test:` - только тесты
- `docs:` - документация
- `refactor:` - рефакторинг

---

### 8️⃣ Согласование перехода

**Перед началом следующей итерации:**

```markdown
## Итерация N завершена ✅

### Что сделано:
- ✅ Задача 1
- ✅ Задача 2
- ✅ Тесты проходят
- ✅ Coverage: XX%

### Следующая итерация: N+1 - Название
Задачи: ...

Переходим к следующей итерации?
```

**Ждать подтверждения от пользователя.**

## ✅ Чеклист для code assistant'а

Перед тем как сообщить "Итерация завершена":

- [ ] Все задачи из тасклиста спринта выполнены
- [ ] Код следует conventions.md
- [ ] Type hints везде (обязательны для всех аргументов и возвратов)
- [ ] Docstrings на русском для публичных методов
- [ ] Логирование добавлено (только logging, не print())
- [ ] Нет дублирования кода (DRY принцип соблюден)
- [ ] Методы не длинные (макс 30-40 строк)
- [ ] Тесты написаны и проходят
- [ ] `make lint` без ошибок
- [ ] `make test` проходит (coverage указан)
- [ ] Критерий готовности проверен
- [ ] Тасклист спринта обновлен
- [ ] Коммит создан
- [ ] Запрошено подтверждение у пользователя

## ⚠️ Важные правила

### ❌ НЕ делай без согласования:
- Не пиши код до согласования подхода
- Не переходи к следующей итерации без подтверждения
- Не коммить без проверки тестов
- Не пропускай обновление tasklist.md

### ✅ ВСЕГДА делай:
- Показывай план ДО реализации
- Жди подтверждения от пользователя
- Обновляй tasklist.md после каждой итерации
- Делай коммит после завершения итерации
- Запрашивай разрешение на переход к следующей итерации
- Не дублируй код - если логика повторяется > 2 раз, вынеси в метод/функцию

### 🎯 Фокус на качестве:
- Каждая итерация = работающий код
- Тесты обязательны
- Coverage > 70% для итераций 2-7
- Линтер должен проходить без ошибок
- Type hints обязательны везде
- Только logging (не print())
- Методы макс 30-40 строк

```markdown
- ✅ Критерий готовности: проверен

\`\`\`bash
make test

- Статус → ✅ DONE

```
