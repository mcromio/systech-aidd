## 📝 Описание спринтов

### FE-S1: Mock API для статистики диалогов

**Цели:**
- Определить функциональные требования к дашборду статистики
- Спроектировать контракт API для фронтенда
- Реализовать Mock API для разработки UI без зависимости от БД

**Состав работ:**
- Анализ и формирование функциональных требований к дашборду на основе существующих данных
- Проектирование REST API контракта (KISS подход: минимальный набор методов)
- Проектирование интерфейса `StatCollector` с возможностью Mock/Real реализаций
- Реализация Mock реализации `StatCollector` с генерацией тестовых данных
- Создание entrypoint для запуска API сервера
- Создание команд запуска и тестирования (Makefile)
- Автоматическая генерация OpenAPI документации

**Детальное планирование:** Plan Mode (будет выполнено перед началом спринта)

### FE-S2: Каркас frontend проекта

**Цели:**
- Сформулировать техническое видение frontend части проекта
- Выбрать оптимальный технологический стек для UI
- Создать структуру проекта с настроенными инструментами разработки

**Состав работ:**
- Создание документа технического видения `frontend-vision.md` (аналог `vision.md` для backend)
- Анализ и выбор технологического стека (фреймворк, библиотеки, инструменты)
- Документирование архитектурных решений через ADR (Architecture Decision Records)
- Создание структуры директорий проекта
- Настройка инструментов: линтер, форматтер, сборщик, тесты
- Создание команд разработки в Makefile (dev, build, test, lint)
- Настройка hot-reload для разработки

**Детальное планирование:** Plan Mode (будет выполнено перед началом спринта)

### FE-S3: Web UI для Telegram чата

**Цели:**
- Реализовать веб-интерфейс для общения с Telegram ботом
- Обеспечить real-time обмен сообщениями
- Создать удобный UX для диалога с ИИ-ассистентом

**Состав работ:**
- Проектирование UI чата (список диалогов, окно сообщений, ввод текста)
- Реализация компонентов чата:
  * Список диалогов с пользователями
  * История сообщений
  * Поле ввода с отправкой
  * Индикатор печати (typing indicator)
- Создание Chat API для взаимодействия с ботом:
  * Получение списка диалогов
  * Получение истории сообщений
  * Отправка сообщений от администратора
  * WebSocket/SSE для real-time обновлений (опционально)
- Интеграция frontend с Chat API
- Обработка состояний загрузки и ошибок
- Адаптивный дизайн для разных устройств
- Тестирование и отладка

**Детальное планирование:** Plan Mode (будет выполнено перед началом спринта)

### FE-S5: Real API и интеграция с БД

**Цели:**

## 🎯 Общие цели Frontend проекта

### Функциональные возможности

1. **Dashboard со статистикой:**
   - Общее количество пользователей
   - Количество диалогов (всего, активных)
   - Количество сообщений (всего, по периодам)
   - Использование инструментов (Wikipedia, WebSearch, DateTime)
   - Средняя длина диалога
   - Активность по времени (графики)

2. **ИИ-чат для администратора:**
   - Веб-интерфейс для общения с ИИ
   - Возможность задавать вопросы по статистике на естественном языке
   - Автоматическое преобразование вопросов в SQL запросы
   - Получение аналитических ответов от LLM

### Технические требования

- Современный адаптивный UI (responsive design)
- Быстрая загрузка и рендеринг (performance)
- Обработка ошибок и граничных случаев
- Покрытие тестами критичного функционала
- Автоматическая документация компонентов
- Соблюдение best practices выбранного стека

## 🔄 Workflow спринта

```
💡 Идея → 📋 Plan Mode → 🔄 Разработка → ✅ Тестирование → 📦 Интеграция
```

Каждый спринт проходит через:

1. **Идея (💡)** - описание в roadmap (текущий документ)
2. **Plan Mode (📋)** - детальное планирование с итерациями в отдельном документе
3. **Разработка (🔄)** - реализация по итерациям с тестами
4. **Тестирование (✅)** - проверка качества и функционала
5. **Интеграция (📦)** - связывание с остальными компонентами

### План Mode

Для каждого спринта создается отдельный файл плана:
- `frontend/doc/plans/fe-s1-plan.md` - детальный план спринта FE-S1
- `frontend/doc/plans/fe-s2-plan.md` - детальный план спринта FE-S2
- и т.д.

План спринта содержит:
- Разбивку на итерации (1-3 дня каждая)
- Конкретные задачи для каждой итерации
- Критерии готовности (Definition of Done)
- Зависимости между итерациями

**Шаблоны планирования:** См. [docs/roadmap_templates/](../../docs/roadmap_templates/)

## 🎓 Принципы разработки

### 1. API-First подход
- Сначала проектируем и реализуем API (FE-S1)
- Затем разрабатываем UI на основе готового API
- Mock API позволяет разрабатывать frontend независимо от backend

### 2. Итеративность
- Каждый спринт - законченный инкремент функциональности
- Можно показать результат после каждого спринта
- Детальное планирование в Plan Mode перед каждым спринтом

### 3. Качество кода
- Тесты для критичного функционала
- Линтер и форматтер в процессе разработки
- Code review перед завершением спринта
- Документирование компонентов и API

### 4. KISS (Keep It Simple, Stupid)
- Минимальный необходимый функционал
- Простые и понятные решения
- Избегаем переусложнения (overengineering)
