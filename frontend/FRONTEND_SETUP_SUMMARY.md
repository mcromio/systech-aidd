## 📋 Описание спринтов (кратко)

### FE-S1: Mock API для статистики диалогов

**Цели:**
- Сформировать функциональные требования к дашборду
- Спроектировать REST API контракт
- Реализовать Mock API для разработки UI

**Ключевые задачи:**
- Анализ требований к дашборду
- Проектирование интерфейса `StatCollector` (Mock/Real)
- Реализация Mock с тестовыми данными
- Создание entrypoint для API сервера
- OpenAPI документация

---

### FE-S2: Каркас frontend проекта

**Цели:**
- Создать техническое видение frontend
- Выбрать технологический стек
- Настроить инструменты разработки

**Ключевые задачи:**
- Документ `frontend-vision.md`
- Выбор фреймворка (React/Vue/Svelte)
- ADR для архитектурных решений
- Структура проекта
- Настройка линтера, форматтера, тестов
- Makefile с командами (dev, build, test, lint)

---

### FE-S3: Dashboard со статистикой

**Цели:**
- Реализовать UI дашборда
- Интегрировать с Mock API
- Обеспечить качество функционала

**Ключевые задачи:**
- UI/UX проектирование
- Компоненты визуализации (графики, таблицы)
- Интеграция с Mock API
- Адаптивный дизайн (responsive)
- Unit-тесты компонентов
- Тестирование и отладка

---

### FE-S4: ИИ-чат для администратора

**Цели:**
- Реализовать веб-чат для ИИ-ассистента
- Создать Chat API
- Реализовать Text-to-SQL механизм

**Ключевые задачи:**
- UI чата (input, messages, history)
- API endpoint для чат-запросов
- Text-to-SQL:
  * Промпт для преобразования вопроса в SQL
  * Выполнение SQL к БД статистики
  * Формирование ответа через LLM
- Интеграция frontend + backend
- Streaming ответов (опционально)

---

### FE-S5: Real API и интеграция с БД

**Цели:**
- Заменить Mock на Real реализацию
- Обеспечить сбор реальной статистики
- Переключить frontend на Real API

**Ключевые задачи:**
- Схема БД для статистики (PostgreSQL)
- Миграции Alembic
- Real реализация `StatCollector`
- Механизм переключения Mock/Real
- Оптимизация запросов (индексы, кэш)
- Переключение frontend
- Валидация данных

## 🚀 Следующие шаги

### Немедленные действия (Plan Mode для FE-S1)

1. **Создать детальный план FE-S1:**
   ```bash

   touch frontend/doc/plans/fe-s1-plan.md
   ```

2. **Заполнить план по шаблону:**
   - Разбить спринт на итерации (1-3 дня каждая)
   - Для каждой итерации: цель, задачи, критерии готовности
   - Добавить Definition of Done (11 пунктов)

3. **Обновить статус в roadmap:**
   ```markdown
   | **FE-S1** | Mock API для статистики диалогов | 📋 Запланирован | [План](plans/fe-s1-plan.md) |
   ```

4. **Начать разработку:**
   - Выполнять итерации последовательно
   - Обновлять прогресс в `fe-s1-plan.md`
   - Проверять Definition of Done

## 💡 Ключевые принципы

### 1. API-First подход
- Сначала API (FE-S1), затем UI (FE-S3, FE-S4)
- Mock API позволяет разрабатывать frontend независимо

### 2. Итеративность
- Каждый спринт - законченный инкремент
- Детальное планирование в Plan Mode

### 3. KISS (Keep It Simple)
- Минимальный необходимый функционал
- Простые решения, без overengineering

### 4. Качество кода
- Тесты для критичного функционала
- Линтер и форматтер
- Документирование компонентов
