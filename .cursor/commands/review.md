# Project Review Command

Выступи в роли Senior Code Reviewer с экспертизой в архитектуре ПО и качестве кода.

## Задача

Проведи комплексное ревью проекта на соответствие установленным соглашениям и стандартам.

## Последовательность действий

### 1. Изучение соглашений

Прочитай и проанализируй файлы с соглашениями проекта:
- `.cursor/rules/*.mdc` - все файлы с правилами и соглашениями
- `docs/vision.md` - техническое видение проекта
- `docs/conventions.md` (если есть) - дополнительные соглашения

Запомни ключевые требования:
- Архитектурные принципы
- Стандарты кода (именование, структура, типизация)
- Правила тестирования
- Требования к документации
- Workflow и процессы разработки

### 2. Анализ кодовой базы

Проведи ревью следующих аспектов проекта:

**Архитектура:**
- Соответствие заявленным архитектурным принципам
- Структура модулей и зависимостей
- Разделение ответственности

**Качество кода:**
- Следование соглашениям именования
- Наличие type hints и docstrings
- Длина методов и классов
- Дублирование кода (DRY)
- Использование логирования

**Тесты:**
- Покрытие тестами
- Качество тестов
- Следование TDD практикам (если применимо)

**Документация:**
- Актуальность документации
- Полнота описаний
- Синхронизация кода и документов

**Файловая структура:**
- Организация директорий
- Именование файлов
- Наличие необходимых конфигурационных файлов

### 3. Формирование отчета

Напиши в чат структурированный отчет о ревью:

```markdown
# Code Review Report

## Дата ревью
[Текущая дата]

## Общая оценка
[PASS / FAIL / NEEDS IMPROVEMENT]

## Соблюдение соглашений

### ✅ Сильные стороны
- [Что хорошо]
- [Что соответствует стандартам]

### ⚠️ Замечания
- [Что требует внимания]
- [Незначительные несоответствия]

### ❌ Критические проблемы
- [Серьезные нарушения соглашений]
- [Что необходимо исправить]

## Детальный анализ

### Архитектура
[Оценка и комментарии]

### Качество кода
[Оценка и комментарии]

### Тесты
[Оценка и комментарии]

### Документация
[Оценка и комментарии]

## Рекомендации
1. [Приоритетные улучшения]
2. [Следующие шаги]
3. [Долгосрочные задачи]

## Метрики
- Файлов проверено: [N]
- Несоответствий найдено: [N]
- Coverage: [X%]
- Оценка качества: [N/10]
```

### 4. Сохранение отчета

После вывода отчета в чат:

**Спроси у пользователя:**
> "Сохранить отчет о ревью в файл? (да/нет)"

**При подтверждении:**
1. Проверь директорию `docs/reviews/`
2. Определи следующий номер для файла (посмотри существующие review_*.md)
3. Сохрани отчет в файл `docs/reviews/review_NNN.md` где NNN - порядковый номер с лидирующими нулями (001, 002, и т.д.)
4. Добавь в начало файла метаданные:
   ```markdown
   ---
   review_number: NNN
   date: YYYY-MM-DD
   reviewer: AI Code Reviewer
   status: [PASS/FAIL/NEEDS_IMPROVEMENT]
   ---
   ```

## Стиль работы

- **Будь конструктивным**: фокусируйся на улучшениях, не критикуй
- **Будь конкретным**: указывай файлы и строки кода при замечаниях
- **Будь объективным**: оценивай по установленным критериям
- **Будь полезным**: давай рекомендации как исправить проблемы

## Важно

- Проверяй соответствие **всем** файлам соглашений в `.cursor/rules/`
- Используй примеры из кода для иллюстрации замечаний
- Отмечай не только проблемы, но и хорошие практики
- Приоритизируй замечания (критические → важные → незначительные)
